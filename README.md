# Weather API

A small experiment in turning weather data into something actually useful.

**Live:** [your deployed link]

---

## Why I built this

I want to build a life where I can work from different places, spend a few months in one city, then move somewhere completely different.

Which means I'm slowly becoming the kind of person who checks the weather before deciding where to go, what to pack, or whether I want to spend the day outside.

So I wanted to build something simple around a question I actually care about:

**What can I do with weather data beyond just showing the temperature?**

The answer started with an API.

I connected the app to a weather API, pulled the data I needed, and built an interface around it.

The interesting part wasn't getting the data.

It was figuring out **what the data should mean to the person using the app.**

---

## What I built

The application takes weather information from an API and turns it into a simple experience for checking current conditions.

Instead of making someone dig through raw numbers, the app focuses on the information that actually matters when you're deciding what to do with your day.

Temperature.

Humidity.

Wind.

Conditions.

Simple inputs, but together they tell a much better story than any one number does.

---

## The idea behind it

A weather API gives you data.

A product gives that data a reason to exist.

That's what I was trying to understand while building this.

If I tell you it's **28°C**, you still don't know whether that's a great day to walk around Mumbai or whether you're going to regret leaving the hotel five minutes later.

Temperature is a number.

**How the day feels is the information I actually want.**

That difference is what made this project interesting to me.

---

## Building it

The workflow is fairly simple:

**User → App → Weather API → Weather data → Useful interpretation → User**

The API handles the information.

The application handles the experience.

And the product thinking sits somewhere in between.

---

## What I learned

This project made one thing very clear to me:

**Getting an API to work is not the same thing as building a useful product.**

The technical part is only the beginning.

You can successfully fetch a JSON response, display every field, and still build something nobody needs.

The harder questions are:

* Which information actually matters?
* What should the user have to interpret themselves?
* What can the product interpret for them?
* How much information is too much?
* What decision is the user actually trying to make?

Those questions are much more interesting to me than simply making another API call.

---

## What I'd improve

This is still a small project, so there are plenty of things I'd change with more time.

* Better weather interpretation
* Forecast information
* Multiple saved locations
* Travel-focused comparisons between cities
* More useful recommendations based on conditions
* Better handling of edge cases and API failures

Eventually, I'd like to push it closer to the question I actually care about:

**"Given where I am and what I want to do, what does today's weather mean for me?"**

---

## Why this project matters to me

This isn't meant to be a revolutionary weather app.

It's a small project built around a much bigger thing I'm learning:

**how to turn raw information into a product that helps someone make a decision.**

And honestly, that's the part of Product Management I'm most interested in.
